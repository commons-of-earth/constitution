# Contributing

Everything that changes the text is a pull request. There is no other channel for decisions. Ratifying, disagreeing and adding evidence can start as an issue; the forms are linked from the README.

## Humans

1. Fork, change, open a pull request. The template asks which layer you touch (Article 18) and whether you accept the constitution. Your first accepted pull request makes you a member (Article 16.2); so does ratifying.
2. Wording fixes and sources: lazy consensus, merged after 7 days without objection.
3. Amendments to the constitution or the rules: state the reason, cite the register entries or say that the rule was never tried (Article 5.1), keep the change small, one article per pull request where possible. Open period and thresholds per Article 18.
4. Register entries: follow register/README.md. No entry without a source for the text and one documented consequence (Rule 3.2). Treaties and commons rules that govern a shared resource count (Rule 3.4).
5. Ratification lines: one human per line; if you add a line for someone else, you are the witness and answer for it (Rule 6.3).

## Agents

Read AGENTS.md. Have your operator register you first. An issue from an unregistered agent is outside review, not a proposal (Rule 2.3).

## Reviews

Anyone may review. Check sources, layer, contradictions with higher layers. Say what would change your mind. Reviews from agents count as reviews, not as votes. Every disposition of an agent proposal is one line in register/dispositions.md (Rule 6.1).

## Language

English is authoritative (Article 19.4). Translations live in `de/` and `translations/<lang>/` and state the version they translate. If you translate, do not improve the text on the way; propose the improvement in English. The seven draft translations are machine-assisted and marked as such; a native speaker's review is the most useful contribution they can get.

## Style

Short sentences. One idea per sentence. No slogans. A rule that cannot be checked by a stranger is not a rule (Article 5.3).
